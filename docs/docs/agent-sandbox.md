# Agent 云沙箱

> 本文介绍面向 AI Agent 的云沙箱（Cloud Sandbox）：它是什么、为什么需要、提供哪些能力，以及典型应用场景。内容整理自各云厂商公开产品资料，性能数据统计于 2025 年 8 月，仅供参考。

## 1. 背景：为什么 Agent 需要云沙箱

2025 年以来，能够自主编写和执行代码的 AI Agent 迅速从实验室走进生产环境。Agent 在执行任务时需要访问敏感资源、执行代码、操作浏览器并与外部系统交互，这对运行环境提出了三方面同时成立的要求：

- 够自由：支持代码执行、浏览器操控、文件读写等多样化任务操作；
- 够安全：Agent 行为存在不可预测性，必须避免误删数据或越权操作；
- 够弹性：支撑大规模并发会话，随用随建、用完即走。

单靠模型或应用层无法同时满足这三点，沙箱因此成为 Agent 从研发走向生产的关键基座：为每一次任务提供一个安全隔离、快速就绪的专属执行环境。

### 1.1 传统容器的局限

标准的 Docker/runc 容器通过 Linux namespace 做隔离，但所有容器共享同一个宿主机内核。在多租户 Agent 场景下，这带来两类风险：

- 内核攻击面：一个用户的会话如果触发内核漏洞，可能影响同节点上所有其他用户的会话；
- 资源失控：一次失控的递归代码生成就可能触发 OOM 或 fork bomb，波及同节点上的全部工作负载。

| 维度     | 传统容器方案                   | Agent 云沙箱                          |
| -------- | ------------------------------ | ------------------------------------- |
| 隔离级别 | namespace 隔离，共享宿主机内核 | VM 级内核隔离，实例间严格隔离         |
| 启动速度 | 秒级                           | 毫秒级（命中预热池约 40 ms）          |
| 弹性伸缩 | 依赖自建编排与扩容             | Serverless 自动弹性，支持批量并发拉起 |
| 状态管理 | 自行处理持久化与清理           | 生命周期托管，销毁后不残留数据        |

云沙箱的目标可以概括为一句话：VM 级的内核隔离，容器级的交付速度——毫秒级启动、自动弹性伸缩、每个会话完全独立。

## 2. 核心概念

Agent 云沙箱是面向 AI Agent、强化学习（RL）训练等应用场景的新一代基础设施，提供安全、隔离、高效、有状态的 Serverless 沙箱环境。用户无需关心底层基础设施，可按需快速拉起沙箱。其概念模型如下：

- 沙箱应用：资源调度与运行的基本单元，由沙箱镜像和沙箱配置构成；
- 沙箱实例：实际执行沙箱镜像的安全且隔离的运行环境，生命周期可自定义；
- 沙箱镜像：沙箱实例的容器镜像，支持开箱即用的公共镜像与业务自定义镜像；
- 沙箱模板：包含预装环境与配置的标准化模板，是批量创建同构环境的基础；
- 预热池（warm pool）：提前创建并待命的实例池，使沙箱创建尽可能命中热路径。

### 2.1 生命周期与会话绑定

沙箱的生命周期通常与用户会话绑定，随会话创建、离线释放。部分场景对启动速度要求极高：用户发出一条消息后，沙箱需要在毫秒级完成初始化并开始执行，冷启动延迟直接影响体验。因此底层依赖预热池与模板机制，让沙箱创建尽可能走热路径；同时实例之间保持严格的状态隔离，销毁后不残留任何数据。

## 3. 核心能力

### 3.1 多种沙箱类型

- 代码沙箱（Code）：支持 Python、JavaScript 等多种编程语言，适用于数据处理、科学计算、图表生成、Vibe Coding 等安全代码运行场景；
- 浏览器沙箱（Browser）：提供安全隔离的浏览器交互与测试环境，降低对本地系统的潜在风险，适用于 Deep Research、通用 Agent 等浏览器操作场景；
- 电脑沙箱（Computer）：提供完整的远程虚拟机操控能力，支持对 Windows、Linux 系统进行鼠标控制、键盘输入、实时截屏等操作；
- 自定义沙箱：按业务需求定制执行环境，包括环境定制（自由选择操作系统、预装软件、依赖库与工具链）和资源配置（按需配置 CPU、内存、存储）。

### 3.2 生命周期管理

支持启动、超时删除、自动空闲回收、暂停与休眠唤醒等能力，在覆盖多样化业务场景的同时降低资源消耗。有状态使用方面，可指定实例长周期运行，让同一会话的多次请求共享同一个沙箱环境；实例休眠后保留文件系统状态，唤醒后可继续运行。

### 3.3 文件操作与外部存储

支持目录与文件的创建、读取、编辑与搜索，为 Agent 提供完整的沙箱内文件管理能力；同时支持外挂存储，对接外部对象存储，实现文件的上传、下载与共享。Agent 因此可以在沙箱内直接处理数据或中间结果，并安全地与外部系统交互。

### 3.4 权限控制

提供细粒度的角色控制，可灵活配置沙箱对云资源的访问范围，在保障安全的同时为 Agent 释放必要的云上操作能力。

### 3.5 接入方式

提供工程师与 Agent 均友好的多样化接入方式：SDK、CLI、MCP、RESTful API，并兼容社区开源沙箱协议，便于既有应用平滑迁移。其中 MCP 接入允许 Agent 把沙箱操作直接当作工具调用，是 Agentic 场景下的典型用法。

### 3.6 弹性与成本

- 极致弹性：支持海量资源与大规模并发拉起，满足高并发训练与推理场景的资源供给；
- 镜像分发：支持千级规模的镜像预热分发，满足多镜像场景下的快速启动需求；
- 毫秒级计费：按请求量和执行时长计费，不执行不收费。

## 4. 性能指标

| 指标项           | 指标值              | 说明                                       |
| ---------------- | ------------------- | ------------------------------------------ |
| 冷启动耗时       | 100 ms              | 无预热实例时，从创建到可服务的耗时         |
| 预热池创建时延   | 40 ms               | 命中预热池时的实例就绪时延                 |
| 休眠唤醒时延     | 秒级（约 1~10 s）   | 实例休眠后保留文件系统状态并恢复运行的耗时 |
| 大规模创建吞吐量 | 最高 12 万实例/分钟 | 面向高并发训练与推理场景的弹性创建能力     |

注：上述数据统计时间为 2025 年 8 月，来自云厂商公开测试结果，具体以各产品最新文档为准。

## 5. 应用场景

### 5.1 强化学习训练

在 Agentic AI 趋势下，模型的 RL/RFT 训练聚焦于增强工具调用、处理复杂任务和代码生成。这类训练需要并发拉起大量沙箱，作为模型任务运行和经验收集的执行环境。云沙箱的弹性能力、海量资源支持与镜像批量分发能力可以直接提升整体训练效率；部分云沙箱还提供与主流 RL 训练框架（如 veRL）深度集成的开箱即用代码沙箱，同时也支持自定义沙箱镜像适配各类训练框架。

### 5.2 在线 AI 应用与智能体服务

通用型智能体应用在完成 Deep Research 等复杂任务的过程中，需要为请求拉起隔离环境来执行 AI 驱动的任务。云沙箱提供 Code、Browser、All-in-One 等公共运行环境镜像，支持开箱即用或基于模板二次开发；其弹性能力可按实时请求量拉起对应数量的实例，以较为经济的方式支撑线上高并发。

## 6. 小结

Agent 云沙箱把"安全隔离、快速就绪、弹性并发"的执行环境做成托管服务：向下用 VM 级隔离解决传统容器的安全短板，向上通过 SDK、CLI、MCP、API 等方式供 Agent 直接调用，并以预热池、模板、镜像分发等机制把启动时延压到毫秒级。对需要落地生产环境 Agentic 应用的团队而言，它是继模型与编排层之后的基础设施标配。
