组合是一种管理复杂性并将代码组织为可复用部分的策略。Lit 提供了几种组合和代码复用的选项：

- 组件组合。
- 响应式控制器。
- 类混入。

[_组件组合_](/docs/v3/composition/component-composition/)是从更简单的组件组装复杂组件的过程。组件可以在其模板中使用子组件。组件可以使用标准 DOM 机制进行通信：在子组件上设置属性，以及监听来自子组件的事件。

虽然组件组合是考虑将复杂 Lit 项目分解为更小单元的默认方式，但还有两种值得注意的代码模式可用于拆分你的 Lit 代码：

[_响应式控制器_](/docs/v3/composition/controllers/)是可以接入 Lit 组件更新生命周期的对象，将与某个功能相关的状态和行为封装到一个独立的代码单元中。

[_类混入_](/docs/v3/composition/mixins/)允许你编写可复用的部分组件定义，并将它们"混入"到组件的继承链中。

混入和响应式控制器都允许你将与给定功能相关的组件逻辑拆分为一个可复用的单元。请参阅下一节了解控制器和混入的比较。

## 控制器和混入

控制器和类混入在某些方面非常相似。它们都可以接入宿主组件的生命周期、维护状态并触发宿主更新。

控制器和混入之间的主要区别在于它们与组件的关系。组件与响应式控制器是"拥有"（has-a）关系，因为组件拥有控制器。组件与混入是"是一个"（is-a）关系，因为组件是混入类的一个实例。

响应式控制器是由组件拥有的一个独立对象。控制器可以访问组件上的方法和字段，组件也可以访问控制器上的方法和字段。但控制器不能（轻易地）被使用组件的人访问，除非组件为其公开了公共 API。控制器的生命周期方法在组件上对应的生命周期方法*之前*被调用。

另一方面，混入成为组件原型链的一部分。混入定义的任何公共字段或方法都是组件 API 的一部分。因为混入是原型链的一部分，你的组件可以一定程度上控制混入的生命周期回调何时被调用。

总的来说，如果你正在决定将一个功能打包为控制器还是混入，你应该选择控制器，*除非*该功能需要以下之一：

- 向组件添加公共 API。
- 非常细粒度地访问组件生命周期。
