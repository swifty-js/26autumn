# 国际化

::: warning 先读这里：Lark Docs **没有**内置 i18n 能力
`DocsConfig` 不存在 `lang` / `locales` / `i18n` 字段，代码库也没有 locale 路由前缀识别、语言回退、运行时 locale 切换等任何实现。

本文描述的是一种**约定式组织方式**：你自己把不同语言放在不同目录，再用已有的 `sidebar` 前缀和 `nav` 链接把它们当成几个平行的文档树。对框架而言，`docs/zh/` 和 `docs/en/` 与 `docs/guide/`、`docs/api/` 没有任何区别。
:::

基于上述前提，推荐的多语言组织方式是：每种语言使用独立的文档子目录，通过路径前缀和侧边栏配置实现语言隔离。无需额外的 i18n 运行时库。

## 基本方案

### 目录结构

```
docs/
├── en/                    # 英文文档
│   ├── index.md
│   ├── guide/
│   │   ├── introduction.md
│   │   └── configuration.md
│   └── api/
│       └── overview.md
├── zh/                    # 中文文档
│   ├── index.md
│   ├── guide/
│   │   ├── introduction.md
│   │   └── configuration.md
│   └── api/
│       └── overview.md
└── ja/                    # 日文文档
    ├── index.md
    └── guide/
        └── introduction.md
```

### 配置

为每种语言配置独立的侧边栏前缀：

```ts
defineConfig({
  docs: "docs",
  baseUrl: "/docs/",
  title: "My Docs",
  nav: [
    { text: "English", link: "/docs/en/" },
    { text: "中文", link: "/docs/zh/" },
    { text: "日本語", link: "/docs/ja/" },
  ],
  sidebar: {
    "/docs/en/": "auto",
    "/docs/zh/": "auto",
    "/docs/ja/": "auto",
  },
});
```

### 生成的路由

| 文件                            | 路由                          |
| ------------------------------- | ----------------------------- |
| `docs/en/index.md`              | `/docs/en`                    |
| `docs/en/guide/introduction.md` | `/docs/en/guide/introduction` |
| `docs/zh/index.md`              | `/docs/zh`                    |
| `docs/zh/guide/introduction.md` | `/docs/zh/guide/introduction` |
| `docs/ja/index.md`              | `/docs/ja`                    |

每种语言的文档被视为**独立的文档树**，拥有自己的侧边栏、路由和搜索范围。

## 语言切换入口

### 导航栏链接

::: danger 导航栏不支持下拉菜单
`NavItem.items` 在类型上存在，`defineConfig()` 也会递归给它们加 `baseUrl` 前缀，**但内置主题的导航栏是扁平渲染的** —— `docs-layout.html` 只读 `item.text` 和 `item.link`，从不渲染 `item.items`。写了嵌套 `items` 不会报错，但它们**在页面上不可见**。

想要下拉菜单，需要自行覆盖 `theme/docs-layout` 模板（参见[扩展默认主题](./15-extending-default-theme)）。
:::

因此，实际可用的做法是把各语言直接平铺在 `nav` 里：

```ts
nav: [
  { text: "English", link: "/docs/en/" },
  { text: "简体中文", link: "/docs/zh/" },
  { text: "日本語", link: "/docs/ja/" },
],
```

导航项的活跃态由布局视图按路径前缀匹配得出（`path === target || path.startsWith(target + "/")`），所以当前语言会自动高亮。点击则触发 SPA 导航到对应语言的首页。

### 页面内语言链接

也可以在页面内容中提供翻译链接：

```markdown
---
title: Introduction
---

**Languages:** [English](/docs/en/guide/introduction) | [中文](/docs/zh/guide/introduction) | [日本語](/docs/ja/guide/introduction)
```

## Unicode 锚点支持

### slugify 的 Unicode 处理

Lark Docs 的 `slugify()` 函数使用 Unicode 属性转义保留非拉丁字符：

```ts
text.replace(/[^\p{L}\p{N}\s-]/gu, "-");
```

`\p{L}` 匹配所有 Unicode 字母（包括 CJK、西里尔、阿拉伯等），`\p{N}` 匹配所有 Unicode 数字。

### 各语言锚点示例

| 标题                      | 生成锚点                |
| ------------------------- | ----------------------- |
| `## 安装指南`             | `#安装指南`             |
| `## インストール`         | `#インストール`         |
| `## Установка`            | `#установка`            |
| `## دليل التثبيت`         | `#دليل-التثبيت`         |
| `## Guide d'installation` | `#guide-d-installation` |

这意味着翻译文档中的标题锚点保持原文可读性，无需手动指定英文 ID。

### 重复标题去重

`createSlugger()` 为同一页面内的重复标题追加数字后缀：

```markdown
## 概述 → #概述

## 详细说明 → #详细说明

## 概述 → #概述-1
```

## 翻译工作流

### 平行目录结构

推荐保持各语言目录结构平行：

```
docs/
├── en/guide/introduction.md
├── zh/guide/introduction.md    ← 对应翻译
└── ja/guide/introduction.md    ← 对应翻译
```

### 处理未完成的翻译

如果某种语言缺少某个页面，该页面 simply 不出现在该语言的路由和侧边栏中——不会报错。

```
docs/en/guide/
├── introduction.md    ✓
├── configuration.md   ✓
└── deployment.md      ✓

docs/ja/guide/
├── introduction.md    ✓
└── configuration.md   ✓
                       ← deployment.md 缺失，不影响构建
```

日文侧边栏只显示两个条目，用户不会看到指向不存在页面的链接。

### Frontmatter 翻译

每个语言版本的 frontmatter 应独立翻译：

```markdown
<!-- docs/en/guide/introduction.md -->

---

title: Introduction
description: Learn the basics of the framework
sidebar_label: Intro

---
```

```markdown
<!-- docs/zh/guide/introduction.md -->

---

title: 简介
description: 学习框架基础知识
sidebar_label: 简介

---
```

## 搜索与多语言

### 默认行为

默认情况下，搜索索引包含**所有语言**的页面。用户搜索时会看到所有语言的匹配结果。

### 搜索索引结构

每个搜索条目包含：

```ts
interface SearchEntry {
  title: string; // 页面标题
  link: string; // 页面路由
  headings: string[]; // 标题列表
  excerpt: string; // 摘要
}
```

### 按语言隔离搜索

如需按语言隔离搜索结果，可以通过部署多个独立站点实现（每个站点使用不同的 `baseUrl` 和 `docs` 目录）。

## 最佳实践

### 1. 保持目录结构同步

使用脚本或 CI 检查各语言目录结构的一致性：

```bash
# 检查中文目录是否缺少英文目录中的文件
diff <(find docs/en -name "*.md" | sed 's|docs/en/||' | sort) \
     <(find docs/zh -name "*.md" | sed 's|docs/zh/||' | sort)
```

### 2. 避免硬编码语言路径

在组件或配置中避免硬编码 `/en/`、`/zh/` 等路径。使用相对于当前 `baseUrl` 前缀的路径。

### 3. 翻译 sidebar_label

确保每个语言版本的 `sidebar_label` 使用对应语言：

```yaml
# en
sidebar_label: Getting Started

# zh
sidebar_label: 快速开始
```

### 4. 独立的站点配置

如果各语言需要不同的站点标题或描述：

```ts
// 方案一：多站点部署（每语言独立构建）
// en.config.ts
defineConfig({ baseUrl: "/en/", title: "English Docs", docs: "docs/en" });

// zh.config.ts
defineConfig({ baseUrl: "/zh/", title: "中文文档", docs: "docs/zh" });
```

```ts
// 方案二：单站点（共用配置，标题取当前页面 frontmatter）
defineConfig({ baseUrl: "/docs/", title: "My Docs", docs: "docs" });
```

### 5. 用 `_` 前缀隐藏未完成的翻译

把文件名或目录名以 `_` 开头（扫描器会跳过），或干脆暂时不提交该文件：

```
docs/ja/guide/
├── introduction.md      ✓ 已翻译
└── _deployment.md       ← 以 _ 开头，不会被扫描
```

## 限制

- **无自动翻译检测**：不会自动提示哪些页面缺少翻译
- **无语言回退**：如果当前语言缺少某页面，不会自动回退到默认语言
- **无运行时语言切换**：语言切换通过 SPA 导航实现，非 i18n 框架的 locale 切换
- **搜索不区分语言**：默认搜索索引混合所有语言（MiniSearch 不支持语言级分词）

对于 CJK 语言的搜索，MiniSearch 使用基于空格的分词——中文等无空格语言可能需要用户输入较长关键词才能获得准确结果。
